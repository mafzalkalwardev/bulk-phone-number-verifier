01What is Bulk Phone Number Verifier?

Bulk Phone Number Verifier (PhoneVerify) is an MIT-licensed web app for cleaning phone lists before SMS or outreach. It normalizes numbers with Google libphonenumber and, in the self-hosted dashboard, compares United States, United Kingdom, and Germany numbers with regulator block data. The browser checker on this site runs only the numbering-plan step, on your device.

Results are labeled structurally valid or block allocated. They are not labeled currently active unless the Live HLR provider is configured.

Numbering-plan specimen

Labels libphonenumber returns for these inputs. Format examples, not proof a line is in service. 555-01 and Ofcom drama numbers are reserved for fiction and still parse as structurally valid.

02Three different answers

The app keeps these checks separate. A pass on one of them does not imply the others.

What each check means and where it runs
Check Where it runs A positive result means
Format, E.164, country, line type Browser checker and self-hosted app The numbering plan accepts the number.
Regulator block allocated or free Self-hosted app, when US, UK, or DE block rows are loaded The prefix is in the loaded block database. Allocated means assigned to a carrier, not that the line is live.
Currently active on the network Self-hosted app, only after HLR keys are set The hlr-lookups.com provider returned an active status for that query.

04Features

In the browser

Numbering-plan check, no account

  • Paste one number per line and set a default country for numbers that omit a country code.
  • Each row is structurally valid, possible but not valid, or invalid.
  • Columns: E.164, country, and line type from libphonenumber metadata.
  • Download the same rows as CSV. The file is built on your device.

Self-hosted

Dashboard, jobs, and exports

  • Upload a CSV or text file, or paste a list. Name the phone column when the CSV header needs it. Up to 100,000 numbers per job.
  • Async jobs with progress, plus a single-number check page.
  • Filters for structurally valid, SMS candidates, unallocated, invalid, and unknown.
  • CSV export: all rows, structurally valid rows, or SMS candidates. With HLR configured, also rows whose live status is active.
  • Coverage page with sync hooks for NANPA, Ofcom, BNetzA, the bundled seed, or all of them.
  • Lookup cache. The default TTL in .env.example is 30 days.
  • Auth.js credentials, Prisma, SQLite by default or PostgreSQL, and an in-process queue or BullMQ when REDIS_URL is set.

Line types the parsers can return

  • mobile
  • fixed line
  • fixed line or mobile
  • toll-free
  • premium rate
  • shared cost
  • VoIP
  • personal number

The self-hosted app reads these from google-libphonenumber. The browser checker reads them from libphonenumber-js max metadata. When metadata has no type, the label is unknown.

05How it works

Clean a list on your server

This is the full workflow: format, regulator blocks, stats, and CSV export. It does not mark a line as currently active unless a Live HLR provider is configured.

  1. Install and start the dashboard. Clone the repository, copy .env.example to .env, install dependencies with npm, run the Prisma migration and the seed script, then start the app with npm run dev. You need Node.js 20 or newer.
  2. Upload a list. Sign in, open Upload, and set the default country used when a number has no country code. Optionally name the CSV phone column. Upload a CSV or text file, or paste one number per line. A job accepts up to 100,000 numbers.
  3. Read the job. Open the job for progress and counts: valid mobile, valid other, unallocated, invalid, and unknown. Each row includes E.164, line type, classification, block status, an internal score, and live status. Live status stays not configured until HLR API keys are set.
  4. Export a CSV. Export all rows, structurally valid rows, or SMS candidates. SMS candidates are structurally valid numbers whose line type is mobile or fixed-or-mobile. If a Live HLR provider is configured, you can also export rows whose live status is active.

Block feeds the importers are written against: NANPA CO code assignments (opens in a new tab), Ofcom numbering data (opens in a new tab), and BNetzA Nummerierung (opens in a new tab). To turn on live status, set HLR_API_KEY and HLR_API_SECRET from your hlr-lookups.com API settings and restart the app. The coverage page then shows Live HLR as configured. Mapped results are active, absent, or invalid.

Check numbering-plan validity without installing

Use this when you only need format, country, and line type.

  1. Open the browser checker. Go to the checker.
  2. Paste the list. Put one number per line. Set a default country for numbers that do not start with a country code.
  3. Read the rows. Choose Check list. Each row is structurally valid, possible but not valid, or invalid, with E.164, country, and line type when the parser has them.
  4. Download CSV. Choose Download CSV. The file is created in your browser.

Limit of this page. The browser checker does not load NANPA, Ofcom, or BNetzA blocks, and it does not call HLR. It does not upload the list.

06Use cases

SMS and outreach lists

Drop numbers the numbering plan rejects, and drop prefixes the loaded block data marks free, before a campaign spends on messages.

CRM and lead operations

Normalize a messy phone column to E.164 and keep the country and line type next to each row.

Agencies and freelancers

Self-host list cleanup and describe the result as structurally valid or block allocated, rather than as a live line.

Developers

Run a Next.js and Prisma pipeline with a LiveLookupProvider slot. The built-in provider is hlr-lookups.com. The code can take another provider through that interface; Twilio, CM.com, CheckMobi, and SIGTRAN are not shipped as integrations.

07FAQ

What is Bulk Phone Number Verifier?

Bulk Phone Number Verifier (PhoneVerify) is an MIT-licensed web app for cleaning phone lists before SMS or outreach. It normalizes numbers with Google libphonenumber and, in the self-hosted dashboard, compares United States, United Kingdom, and Germany numbers with regulator block data. The browser checker on this site runs only the numbering-plan step, on your device.

Can it tell if a phone number is currently active?

No. Format checks and regulator block checks do not mean a SIM is registered on a carrier network. Currently-active status is available only after you set HLR_API_KEY and HLR_API_SECRET for the built-in hlr-lookups.com provider. Until then, results are labeled structurally valid or block allocated, not live.

Which countries does it cover?

libphonenumber format checks are global. Number-block data is for the United States (NANPA), the United Kingdom (Ofcom), and Germany (BNetzA). The repository seed loads example blocks for those three countries. A valid number in a country with no block rows is classified unknown / no coverage.

Does the browser checker upload my numbers?

No. The page at /app/ parses numbers in your browser and builds the CSV on your device. It does not run regulator-block lookups or HLR lookups, and it does not send the list to a server.

Does the self-hosted app send numbers to a third party?

Not for structural or block checks. Those run on your machine or server. You can optionally sync NANPA, Ofcom, or BNetzA files yourself. A live lookup is sent to hlr-lookups.com only when the HLR keys are set. Set HLR_BULK_ENABLED to false to keep live checks on the single-number page and skip them during bulk jobs.

What do the classifications mean?

Invalid means the numbering plan rejects the number. Unallocated means it is valid and the loaded block data marks that prefix free. Structurally valid means it is valid and not sitting in a free block. An allocated block is a regulator assignment of that range, not proof the line is in service. Unknown / no coverage means the number is valid but that country has no block rows loaded. If the country does have block rows and this prefix is simply missing, the row stays structurally valid and the block status is unknown. The internal score weights format, line type, and block status (and live status when HLR is on). It is not a measured accuracy rate.

What is an SMS candidate?

An SMS candidate is a structurally valid row whose line type is mobile or fixed-or-mobile. The job page can export those rows as CSV. A valid mobile classified unknown, because its country has no block data, is not included in that export.
